# Gemini添削による文書の再利用性比較

構成を保って平易な日本語にする追加試行は[別の記録](plain-japanese-evaluation.md)にまとめた。目的・実行・判定をこの再構成の試行とは分ける。

Issue #99。Gemini 3.6 Flashで移行案を添削し、会話を知らない読者役が同じ5問に回答できるか比較した。**今回の1例では、添削による再利用性の明確な改善は確認できなかった。候補は未採用とし、既存の移行案とimplement/scopingは変更しない。**

原文でも次の判断に必要な情報の大半は抽出できた。一方、原文・添削案の双方からgateの条件を弱く解釈する回答が出た。文章の添削だけでなく、次の担当が重要な条件を正しく説明できるかを確認する必要がある。

## 対象・方法

- 原文は[PR #98の文書](https://github.com/thkt/dotagents-workflow-trial/blob/c309e0488a2730a0b94c0eccf609bcfea3663481/docs/workflow-refinement/agents-migration-plan.md)。実行時mainは `b97883689235671ae84a1f13f55a24aa89d00ae1`。原文17697文字、142行。
- Antigravity CLIのモデル一覧から `gemini-3.6-flash-high` を選択し、各実行のstream-json initで同じIDを確認した。別モデルへの切替なし。
- 原文の読者確認、添削、添削後の読者確認を各1回、新規会話で実行。過去会話・前段の回答は渡さず、各資料全文と[読者質問](reader-prompt.txt)または[編集指示](editing-prompt.txt)だけを渡した。ツール操作を禁止し、保存されたtoolイベントは3回とも0件。
- `agy --model gemini-3.6-flash-high --output-format stream-json --print-timeout 5m --sandbox -p PROMPT`を使用。各回5分以内、再試行なし。モデル一覧の確認前には旧CLIの通常起動でTTYエラーがあり、添削実行としては数えない。
- [原文の回答](reader-before.txt)、[添削案](edited.txt)、[添削後の回答](reader-after.txt)は応答の原文。相対リンクは元の文書配置を前提とした生成結果であり、保存先に合わせて修正していない。未採用の比較資料なので現行手順として使わない。

## 結果

| 観点 | 原文の読者確認 | 添削後の読者確認 |
| --- | --- | --- |
| すぐ移行可能か・次の判断と調査 | 未合意・条件不足を示し、repo範囲やホスト登録等を抽出 | 同様に抽出 |
| 再利用資産・Code/cleanup/状態の互換性 | 保持対象と、そのまま移行できない条件を抽出 | 同様。ただし旧build/executionまで「再利用できる資産」の列挙に含め、置換候補と確定した再利用の区別が弱い |
| 別repo/OS・公開主体 | repo/App固定・Keychain依存、gh/Git/Appの分担を抽出 | 同様に抽出 |
| 停止・復帰・公開済み操作 | 停止条件、旧設定の復元、ファイル復元で公開は取り消せない点を抽出 | 同様に抽出 |
| gateと未確認範囲 | 合意・真実性の保証ではない点は抽出。ただし成功条件を「評価が存在すること」と説明 | 同じ弱い解釈が残る |

gateの説明は[discovery-input.ts](../../../scripts/discovery-input.ts)のsession/readyと[discovery.ts](../../../scripts/discovery.ts)のassess/gateに照合した。保存済み評価の存在だけではなく、revisionとの整合、基準の整合、missingがないこと等を確認している。原文の「保存済み評価のみを見る」という表現では、この違いを読者が落とす可能性がある。今回の添削はそれを修正しなかった。回答が誤る原因を文書だけに断定するものではない。

添削案は判断手順を比較表より前に配置したが、17097文字・158行で、文字数の減少は約3.4%。大きな表と説明の分散も残る。原文の読者は制限や互換性が複数表へ分散していると指摘し、添削後の読者も認証・未監査事項・gateの説明の分散を指摘した。

原文と候補の差分を親が照合したところ、少なくとも以下の明示が省かれていた。

- 稼働中SQLiteやGitの部分コピーを整合したバックアップと見なさない条件（書き込み停止・復元確認自体は残る）。
- 旧checkoutを元の場所に保持する理由である絶対パス・実体パスhashへの依存と、復帰成功には実確認が必要という説明。
- 公開済み変更の修正・取消が必要な場合の権限確認。

残る文章で一部は補えるが、情報を保持した単純な再構成とは評価しない。候補の題名も「移行案」から「判断指示書」と強くなっている。本文の未合意の留保は維持されているものの、提案としての読み方は原文の方が明確である。

## 実行量・限界

[モデル・時間・usage・応答hash](results.json)を保存した。原文読者約23.9秒、添削約51.3秒、添削後読者約18.0秒。これは生成の壁時計時間で、人の読了・探索時間ではない。キャッシュ量・出力量等も異なるため、添削後の短い時間を理解の改善とは扱わない。

同一モデルが編集と読者確認を担当した1文書各1回の比較。会話は分けたが、独立した人間の評価やモデル間の比較ではない。資料全文を直接渡しており、READMEから探す行動、実際のscoping CLI、チームメンバーによる利用、実移行は未検証。新しい事実の調査を禁止しているため、原文の事実をGeminiが検証した実験でもない。親による照合は主要な条件を対象とし、全主張の完全監査ではない。

生のCLIログと入力全文は実行ホストの一時領域 `doc-reuse-gemini36/` に保持し、公開対象はこの記録・必要な指示・応答・集計だけとした。一時領域の永続性には依存せず、原文は固定commitから参照できる。

## 次に改善する対象

Geminiの常設・必須化を決める根拠には不足している。まず、文書の更新時に「次の読者が何を判断するために使うか」を具体化し、その判断に必要な条件が誤読されないかを確認する。今回ならgateの説明を正確にし、採用済み資産と置換候補を明確に分けることが、全文の添削より先に必要な改善である。これは次の変更候補であり、この実験では現行文書・方針へ自動適用しない。
